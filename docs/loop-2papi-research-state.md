### Виток 1/5 — угол: prompt caching × токен-сейверы ✅
- находки (верифиц.: docs Anthropic/OpenAI, tokenpricing.dev, multigrid.ai):
  1) Кэш = точное совпадение префикса; иерархия tools→system→messages;
     изменение уровня инвалидирует его и всё ниже ⇒ Caveman (system) бьёт
     весь кэш, RTK/Headroom (messages/tool_results) — кэш диалога.
  2) Цены: Anthropic write 1.25×(5м)/2×(1ч), read 0.1× (−90%); break-even
     2-й запрос (5м)/3-й (1ч); OpenAI auto 50% (старые)/90% (GPT-5.x,
     write 1.25×); Gemini 75%, но почасовая оплата хранения.
  3) Роутеры теряют клиентский кэш ротацией апстримов (multigrid) — нужен
     session affinity.
- решения: (а) фича «cache-aware savers»: сейверы трогают только хвост после
  breakpoint, никогда tools/system; (б) sticky TTL ≥5мин как дефолт = кэш-
  preserving routing — клин против OpenRouter; (в) в дашборд cached_tokens/
  hit-rate per key; (г) маркетинг «we don't bust your cache» с замером.
- метрика: 4 верифиц. источника, 4 решения.
- дальше: виток 2 — RP/SillyTavern потребительский сегмент.

## Подцикл B: фри-план (старт 2026-08-21)

Решение владельца ✅: фри-план с бесплатными моделями БУДЕТ.
Задача: спроектировать free tier — supply (легальность!), механика, лимиты.
Критерий: дизайн фри-плана без юр.мин и с понятной экономикой.
Стоп: 3 витка | критерий | 2 без прогресса.

### B-виток 1/3 — угол: ToS фритиров ✅
- находки (верифиц.: ai.google.dev/terms + форум Google 2026-04,
  conductatlas Cerebras ToS, ianlpaterson аудит):
  1) Google free tier: proxy/resell/public production app = нарушение ToS
     (прямо словами); данные фритира идут в тренировку Google; EEA/UK —
     только Paid для API-клиентов. ⇒ ИСКЛЮЧИТЬ из supply.
  2) Cerebras: «Prohibition on Reselling» (high), лицензия отзываемая,
     каталог волатилен (12→2 модели без уведомления). ⇒ НЕ ядро supply.
  3) Groq standard free tier — commercial allowed (единственный крупный;
     перепроверить при онбординге); TPM-потолки реальные ограничители.
  4) Mistral — по-модельные caveats; Cohere trial — non-commercial
     (пример полного запрета).
  5) Экономика альтернативы: фри-план на ПЛАТНОМ DeepSeek Flash с капом:
     ~$0.00032/запрос ⇒ 20 rpd/юзер = $0.0064/день ⇒ 1000 фри-юзеров
     ≈ $190/мес — предсказуемо и без юр.рисков.
- решения: (а) фри-план = платные дешёвые эндпоинты с жёстким дневным
  капом (не квоты фритиров); (б) Groq — вторая полоса где легально;
  (в) спонсорские соглашения с провайдерами (путь OR) — цель Фазы 2+;
  (г) фритиры провайдеров НЕ используем как supply вовсе.
### B-виток 2/3 — угол: механика фри-плана ✅
- дизайн (синтез витков B1+4+юнит-экономики): supply = платные дешёвые
  эндпоинты + Groq-полоса; лимиты 20 rpd / 5 RPM / ctx 32K / out 1K;
  меню 2–3 модели; фри-запросы последними в очереди (fair-use);
  конверсия: счётчик лимита, цена продолжения в момент капа ($0.001/req),
  пополнение = перманентный анлок; предохранитель: дневной бюджет
  фри-COGS с временной деградацией капов и прозрачным баннером.
- решения: дизайн зафиксирован; брендинг «free forever» честен, т.к.
  себестоимость ограничена конструкцией, а не надеждой на порядочность.
### B-виток 3/3 — угол: конверсия free→paid ✅
- находки (верифиц.: OpenView/ChartMogul/Growth Unhinged/Pulseahead 2026):
  freemium self-serve = 2–5% типично, 6–8% отлично; dev-tools — верх диапазона;
  ungated freemium 7–9%; reverse trial медиана ~8%; CC-trial конвертит 5x,
  но режет сигапы (мы карты уже отвергли); мерить когортами 3–6 мес.
- решения: (а) план-цифра: 1000 фри-юзеров ⇒ 25–50 платящих ($250–500/мес)
  против COGS фри-плана ~$190/мес ⇒ фри-план окупает себя уже на бенчмарк-
  конверсии; (б) reverse trial («7 дней премиум-моделей») — тест в Фазе 2;
  (в) KPI цикла: платящих на 1000 посетителей, не % конверсии.
- метрика: 6 источников, 3 решения.
### B-виток 3½ — решение владельца: фри-план v2 ✅
- спека владельца: единственный лимит фри-юзера = 50М токенов/день;
  регулировка лимитов ПО МОДЕЛЯМ — вручную из админки оператора;
  supply = СВОИ ИСТОЧНИКИ владельца (+ бесплатные полосы как довесок);
  бюджет перелива ≤$10/мес.
- реализация (вся машинерия есть): tier-политика = модель→лимит токенов/день
  (таблица + страница Free tier в админке); проверка в policy.go рядом с
  бюджетной; свои источники = аккаунты оператора с весами (source-agnostic);
  перелив на платный DeepSeek ~$10 = один выжатый юзер-день/мес.
- риски приняты владельцем: ёмкость легальных фритиров мала (TPM) ⇒ очередь;
  серые источники на hosted = точка отказа при банах (флаг микса — его выбор).

### C-виток 1/3 — угол: механика IP/device-якорей ✅
- находки (верифиц.: WorkOS Radar, Cloudflare multi-user IP blog,
  peakhour, bootstrapsecurity bypass-разбор):
  1) Чистый IP-лимит слаб: ротация прокси обходят; CGNAT/офис/VPN шарят
     IP тысячами юзеров ⇒ невинные страдают. CF повышает порог для
     multi-user IP консервативно, не банит.
  2) Паттерн Radar: гибрид fingerprint+IP; при атаке режут fingerprint —
     остальные с того же IP работают.
  3) Векторы обхода к закрытию: множественные ключи (лимит 5/юзер),
     X-Forwarded-For спуфинг (доверять только TRUSTED_PROXY),
     header-манипуляции, session-farming.
  4) У API-продукта device_id живёт только в дашборде/сигапе; на гейтвее
     якоря: key → user → IP (+device как сигнал сигапа).
- решения: иерархия якорей key(50M) → user → IP(мягкий ~150M + ≤5 новых
  ключей/день) → device_id(salted hash при сигапе); >2 аккаунтов/device =
  флаг оператору; Fingerprint Pro $99 — при инцидентах.
- метрика: 4 источника, схема из 5 компонентов.

## Подцикл D: антиабьюз v3 — мультиаккаунтинг (сибилы)

Задача: защитить фри-лимит от фермы аккаунтов одного человека
(50M ткн/день × N аккаунтов). Критерий: механизм, делающий ферму
бессмысленной экономически/технически. Стоп: 2 витка | критерий.

### D-виток 1/2 — угол: sybil-resistance практики ✅
- находки (верифиц.: stripe.com 3 гайда 2026, fingerprint.com, seon.io,
  didit.me):
  1) Рецепт Stripe — LINK ANALYSIS: атрибуты идентичности = узлы графа
     (email/device/IP/телефон/платёжка); аккаунты с общим узлом связаны;
     кластер по окнам кампаний; confidence-score, не бинар; от подтверждён-
     ного абьюзера раскручивать граф ретроспективно.
  2) Дешёвые сильные связи: нормализованный email (+tag/dots gmail),
     ПОВТОР ПАРОЛЯ-хэша через аккаунты (фермеры ленятся), платёжный
     инструмент (связывает намертво при первом топапе), ASN//24-подсети,
     velocity (>3 сигапов/device/24ч).
  3) Философия enforcement — ступенчато: low risk = ничего; medium =
     step-up (phone с carrier lookup); high = ГЕЙТ ЦЕННОГО ДЕЙСТВИЯ
     (не блокировать сигап, а закрыть фри-лимит до проверки).
  4) Поведенческий паттерн фермы: сигап → сразу ключ → максимальный
     токен-дрейн → dormant. Аномалия «одинаковые паттерны у аккаунтов
     одного дня создания».
- решения: концепция IDENTITY CLUSTER (union-find по общим узлам) +
  лимит фри-тира на КЛАСТЕР, не на аккаунт ⇒ ферма из N аккаунтов даёт
  N×0 дополнительных токенов математически. Детали в спеке.
- метрика: 6 источников, ядро дизайна.
