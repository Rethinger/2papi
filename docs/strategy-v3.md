# 2papi — стратегия трёх изданий (v2, после ответов владельца)

Дата: 2026-08-21 · Статус: черновик стратегии

## Решения владельца

- Hosted = дешёвый доступ ДЛЯ ВСЕХ сегментов (массовый рынок).
- Цель = компания на годы (не быстрый кэш).

## Следствия из решений (главное)

1. «Дёшево + на годы» исключает серое предложение (пул потребительских
   аккаунтов claude.ai/codex в коммерческом масштабе) — такие сервисы живут
   месяцы и умирают с баном. OSS остаётся BYOA-пулингом (ответственность юзера),
   hosted строится на официальных API дешёвых провайдеров.
2. Конкурировать «ещё одним роутером» с OpenRouter/agentrouter — гонка на дно.
   Козырь 2papi, которого нет у конкурентов: **токен-сейверы** (RTK −20–40%
   input, Caveman до −65% output, Headroom). Позиционирование не «дешёвый
   токен», а «дешевле стоимость задачи» (effective cost per task).
3. Массовость ⇒ антиабьюз обязателен с первого дня: стартовые кредиты малые
   ($1–3, НЕ $200 как у agentrouter — магнит для фарма), верификация по уровням
   доверия, лимиты RPM/день по тиру ключа.

## Матрица изданий

| | OSS | Hosted | Enterprise |
|---|---|---|---|
| Для кого | девы, self-host, BYOA | массовый рынок: дешёвый доступ | компании: комплаенс, VPC |
| Предложение | пулинг своих аккаунтов | офиц. API дешёвых провайдеров + сейверы | то же + Azure/Bedrock/Vertex, SSO, аудит |
| Монетизация | нет (воронка) | prepaid-кредиты, наценка ~15–30% | годовая лицензия + SLA |

## Предложение на старте hosted (supply)

Официальные API дешёвого сегмента: DeepSeek, Zhipu GLM, Qwen, MiniMax,
Gemini Flash, Groq/Cerebras free-tier. ⚠️ По ресёрчу ToS: OpenAI/Anthropic
на hosted v1 НЕ брать (запрет ресейла у Anthropic, серая зона pass-through
у OpenAI) — добавить премиум-тир позже, когда будет объём/партнёрство.
Минимум 3 семейства моделей с первого дня (DeepSeek официально готовит
повышение цен). Free-тариф — только на бесплатных апстримах (ноль себестоимости).

## Экономика (структурно, порядок цифр)

- Наценка 15–30% на дешёвые модели ≈ всё равно кратно дешевле премиум-моделей
  ⇒ «дешёвый доступ» достигается миксом моделей, не демпингом.
- Токен-сейверы −20…−40% среднего чека ⇒ маржу держим при тех же ценах.
- Платёжные издержки: MoR ~5%+фикс (карты), крипта ~0, локальный эквайринг 2–3%.

## Владелец: Украина ⇒ юрлицо и платежи

- Санкционных ограничений нет (стоп-листы MoR — только оккупированные
  территории + РФ/РБ; проверено по Paddle Supported Countries, 2026-08).
- Платёжный стек:
  1. MoR (Paddle ~5%+$0.50 / Dodo дешевле) — карты мира, они платят VAT/налоги
     с продаж, выплаты на UA-счёт 2×в месяц. Чекаут-линк → вебхук → кредиты.
  2. USDT — ⚠️ КОРРЕКЦИЯ ПО РЕСЁРЧУ (2026-08-21): прямой приём крипты на
     ФОП-ЄП запрещён (расчёты только денежной формой, п. 291.6 ПКУ; крипта =
     товар; риск аннуляции упрощёнки + доначисления). Варианты: процессор с
     фиатными выплатами на счёт ФОП, либо крипта-рельс отложить/на физлицо
     до ясности с законом №10225-д. Детали: 2papi-cloud-research.md.
  3. WayForPay/Fondy — позже, для оплат в UAH.
- Юрформа: старт ФОП 3 група (5%, день через Дію) → ТОВ (Дія.City) на
  enterprise-фазе (B2B-контракты/найм/инвесторы).
- Следствие: внешний платёжный блокер СНЯТ, Фаза 1 зависит только от кода (Фаза 0).

## Антиабьюз-минимум (hosted MVP)

- Email-верификация; телефон или микро-списание с карты для повышенных лимитов.
- Старт $1–3 кредитов + free-тариф только на бесплатных апстримах.
- Тиры доверия: лимиты RPM/день/месяц растут с репутацией аккаунта.

# Фаза 1 — 2papi Cloud: техплан

## Что уже есть в кодовой базе (переиспользуем)

- `teams` (010): тенанты с бюджетом, шаринг бюджета между ключами команды.
- Гейтвей (internal/policy): дневные бюджеты ключа И команды, метеринг
  переживает adoption снапшота, блок `budget_exceeded`.
- `request_events.cost_usd`, `key_spend_daily`, `model_pricing` (009):
  метеринг и прайсинг готовы.
- Immutable snapshots + acks: публикация конфига оператором.
- Envelope encryption секретов (secret_records): ключи провайдеров прячем от
  тенантов по умолчанию.

Ключевой вывод: изоляция тенантов идёт через virtual_keys→team_id при ОДНОМ
глобальном снапшоте моделей/роутинга. Полный tenant-scoping снапшотов НЕ нужен
на старте. Оператор правит модели, тенант видит только каталог + свои ключи.

## Миграция 011 — пользователи и RBAC

- `users`: id, email (lower unique), password_hash (bcrypt/argon2),
  email_verified_at, platform_role ('user'|'operator'), disabled_at.
- `sessions`: токен-cookie для Next.js дашборда (проще JWT).
- `team_members`: team_id, user_id, role ('owner'|'member').
- teams += trust_tier int (0/1/2), status ('active'|'suspended').
- Signup API: register → verify email → создать user + личную team +
  первый virtual_key.

## Миграция 012 — кредитный леджер

- `credit_transactions`: id, team_id, delta_usd (+/-), kind
  ('topup'|'bonus'|'refund'|'adjustment'), source
  ('paddle'|'crypto_usdt'|'manual'|'signup_bonus'), external_id,
  UNIQUE(source, external_id) ← идемпотентность вебхуков.
- `teams.balance_usd numeric(12,6)` — обновляется В той же транзакции, что
  вставка леджера (быстрое чтение + аудируемый журнал).

## Энфорсмент баланса (маленькая правка policy.go)

- effective_budget(team) = min(team.budget_usd если > 0, team.balance_usd).
- Баланс уходит в гейтвей через существующий механизм снапшота (поле
  Team.CreditBalanceUSD); списание — control-plane декрементит balance_usd по
  request_events.cost_usd (тот же поток, что key_spend_daily).
- Ночной reconcile: баланс = SUM(delta) − SUM(spend) от начала, расхождение —
  алерт. Нулевой/минус баланс → ключи команды блокируются (уже есть механизм).

## Платежи

- Paddle: продукты-паки $5/$20/$50; webhook `/api/webhooks/paddle`
  (верификация подписи публичным ключом, env) на transaction.completed →
  custom_data.team_id → INSERT ... ON CONFLICT DO NOTHING → balance += delta
  → audit_event. Чекаут — Paddle.js overlay со страницы Billing.
- USDT (semi-auto v1): страница показывает адрес + сумму + код-мемо; юзер
  вводит txid → «pending» → оператор подтверждает в админке → тот же путь
  credit_transactions, external_id = txhash. Автоматизация (TRON watcher /
  Cryptomus) — Фаза 2.
- Signup bonus: грант $1–3 после верификации email, source=signup_bonus.

## Админка оператора (platform_role='operator')

Существующий дашборд + страницы: юзеры и команды (suspend/restore),
балансы, ручные корректировки кредита, очередь подтверждений USDT,
здоровье провайдеров (quota-виджеты уже есть), выручка из леджера.
Тенант видит только свою команду: ключи, usage, баланс, биллинг.

## Антиабьюз тиры (trust_tier)

- tier 0 (новый): только cheap/free модели, низкий RPM, до первого топапа
  или верификации.
- tier 1: после топапа ≥$5 или verified phone — полный каталог, выше лимиты.
- tier 2: объём/репутация — кастомные лимиты вручную оператором.

## Деплой

- Один VPS в ЕС (Hetzner, ок из Украины), существующий compose-стек
  (postgres/redis/gateway/control-plane) + Caddy TLS.
- Домены: cloud.2papi.* (лендинг+дашборд), api.2papi.* (гейтвей).
- pg_dump крон + проверка восстановления ДО запуска (деньги же).

## Что НЕ строим в Фазе 1

Подписки/recurring, PDF-инвойсы, KYC-провайдера (ручной обзор), мультирегион,
SSO организаций, автоматический крипто-watcher.

## Порядок работ

1. LICENSE (Apache-2.0) + edition-gate скелет (build tag `cloud`).
2. Миграции 011/012 + signup/login API + тесты.
3. Кредиты в policy.go + reconcile-джоба.
4. Paddle-вебхук + Billing-страница + USDT-manual.
5. Страницы тенанта (ключи/usage/billing) и админка оператора.
6. Тиры + антиабьюз, деплой на VPS, E2E прогон существующим test/e2e.mjs
   + новый сценарий «регистрация→топап→запрос→списание».

# СТРАТЕГИЯ v3 — пивот: OSS и Enterprise главные (2026-08-22)

Решение владельца: опенсурс и корпоративное — основные направления.
Cloud не отменяется, но демотируется до PLG-витрины. Модель — open-core
по шаблону LiteLLM: OSS побеждает разработчиков ⇒ Enterprise конвертирует
организации. Выполнено уже: LICENSE Apache-2.0 ✅, edition-gate ✅
(`2papi.license` с префиксом `ent:` открывает enterprise-пути).

## Матрица изданий v3

| | OSS (первоклассный продукт) | Cloud (PLG-витрина) | Enterprise (основной доход) |
|---|---|---|---|
| Роль | дистрибуция, доверие, GitHub | самоналив воронки в Ent | годовые лицензии $3k–30k+ |
| Что входит | всё текущее ядро + адаптеры топ-провайдеров, docs, Prometheus, Index | спроектированный стек (кредиты/биллинг/антиабьюз) как hosted demo | лицензия на тот же бинарь |
| Монетизация | нет | кредиты (тонкой лентой) | годовая цена от ёмкости, не за токен |

## Enterprise-гейтинг (по якорям LiteLLM; у нас уже есть база)

Гейтится лицензией `ent:`:
1. SSO/SAML/OIDC для дашборда (+SCIM позже); JWT-auth для API.
2. Организации над командами + роли org/team admin (у нас teams есть,
   organizations добавить).
3. Аудит-логи с ретеншном и экспортом (audit_events уже есть).
4. Secret managers (Vault/KMS) + автоматическая ротация ключей
   (secret_records с envelope encryption — база готова).
5. IP ACL (CIDR), блокировка admin-маршрутов.
6. Guardrails per-key/team: hide-secrets, PII-masking пресеты.
7. Мультирегион control-plane / air-gap.
8. **Claude Code Gateway Protocol** сертифицированно (Anthropic сам
   документирует) + MCP gateway — клин, которого нет ни у кого на Go.
9. Брендинг Swagger/email; AI Hub страница моделей.
10. Поддержка: выделенный канал; 24/7 SLA за доплату.

НЕ гейтится (остаётся в OSS): ключи/бюджеты/лимиты, команды, логи,
Prometheus, фолбэки, guardrail-фреймворк, сейверы, консоль-виджеты.

## Принцип: OSS = селфхостед-прокси для энтузиастов (цикл J)

Оригинальная идентичность 2papi («легковесная альтернатива 9Router/
OmniRoute») остаётся ЯДРОМ OSS-издания, а не жертвой пивота:
- один артефакт для всех аудиторий: энтузиаст/homelab (пул своих
  подписок и аккаунтов, curl|sh за 30с, TUI, виджет-консоль, нулевая
  конфигурация free-провайдеров) ↔ команды (тот же бинарь растёт до
  Enterprise лицензией). Форков и веток нет — издание отличается только
  лицензионным файлом;
- enterprise-фичи БЕЗ лицензии спят (edition-gate деградирует в oss) —
  дефолтный опыт энтузиаста не пухнет;
- правило на каждый шаг хребта: «не ломать DX энтузиаста» (30с-установка,
  ноль обязательных конфигов, ноль телеметрии наружу — это продающее
  свойство, как у LiteLLM);
- E1-задачи (адаптеры, docs, метрики) обслуживают энтузиаста в первую
  очередь — он же главный разносчик по GitHub.

## Очередь Build при параллельных трёх треках («хребет»)

Каждый шаг двигает минимум два издания:
1. License-key сервис (Ent): Ed25519-подписанная офлайн-лицензия
   `ent:...`, валидация в internal/edition; trial-key генератор.
2. Prometheus /metrics + audit_events экспорт (OSS витрина + Ent гейт).
3. Organizations над командами + роли org/team admin (Ent) — таблицы и
   policy-проверки.
4. SSO/OIDC для дашборда (Ent) поверх users/sessions из 011.
5. Адаптеры топ-провайдеров через sources[] (OSS витрина + Cloud supply).
6. Signup/кредиты/policy-баланс (Cloud) — миграции уже готовы.
Ритм соло: спринт = 1 шаг хребта до зелёных тестов, затем витрина/демо
этого шага. Не три задачи в день, а три издания на одном хребте.
